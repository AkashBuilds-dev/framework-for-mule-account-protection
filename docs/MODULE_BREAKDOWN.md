# MuleShield Modules A–J

| Module | What it does | Technology | Output | Key stat | Judge point |
|---|---|---|---|---|---|
| A — Data | Creates geographically distributed synthetic transactions, accounts, ATMs, and fraud patterns for repeatable demonstrations. It gives all downstream models a consistent controlled dataset. | Python, Faker-style synthetic generation, Indian-city coordinates | Training and demo data | 13 cities | Safe, reproducible prototype data without exposing citizen records. |
| B — Mule Detection | Scores individual accounts and transactions using behavioural and transaction signals. It produces the initial risk score for triage. | CatBoost, XGBoost, LightGBM ensemble | Mule risk score and explanation inputs | 18 features | Ensemble design is feasible for a bank-side inference service. |
| C — Syndicate Graph | Links accounts and transfers to expose coordinated rings rather than evaluating accounts in isolation. It adds network context to the risk signal. | PyTorch Geometric / graph analytics | Ring memberships and graph risk | 5 rings | **Syndicates, not individual accounts.** |
| D — Cash-Out Prediction | Predicts where a flagged money trail is likely to be withdrawn as cash. It ranks spatial zones instead of merely raising a fraud alert. | Hybrid spatial model, DBSCAN-style clustering, grid ranking | Ranked 449-cell cash-out heatmap | **80% Precision@Top-10** | Directly answers SIH26184: predict the likely cash-out location. |
| E — Backend Orchestration | Exposes models, cases, alerts, field data, and operations workflows through a central API. It coordinates state and real-time events. | Python, FastAPI, WebSocket | 24+ API routes and event hub | <2 sec event propagation target | Clear separation between intelligence services and role clients. |
| F — Investigator Dashboard | Gives investigators a forensic view of risk, alerts, maps, and syndicate intelligence. It is the command point for initiating controlled critical scenarios. | React, map visualisation, WebSocket | Investigator case and alert workspace | Live alert feed | Converts model output into an actionable investigation. |
| G — Bank and Admin Dashboards | Lets bank officers review freeze actions and lets supervisors monitor escalation compliance. It adds operational accountability to detection. | React Router, Recharts, shared UI | Freeze queue, audit/SLA console | SLA countdowns | Different users receive the workflow they actually own. |
| H — Escalation Matrix | Applies CRITICAL, HIGH, MEDIUM, and LOW workflows with notifications, SLA tracking, and resolution state. It ensures urgency drives a repeatable response. | FastAPI services, in-memory prototype state, WebSocket events | Freeze suggestions, logs, SLA records | CRITICAL: 5 min | Demonstrates policy-aware action, not only classification. |
| I — Field Officer PWA | Delivers assigned dispatches to a government-branded mobile field terminal. It includes routing, ETA, arrival, and action reporting. | React PWA, MapLibre/Maps-style route UI, WebSocket | Mobile dispatch and field report | 2.3 km controlled route | Closes the loop from HQ intelligence to on-ground response. |
| J — Integration and Demo Readiness | Connects the role workflows into one repeatable end-to-end scenario, with audit evidence and fallback operating procedures. It validates the story under a multi-device demonstration. | LAN deployment, WebSocket event flow, QA/checklists | Four-client critical-alert cascade | 4 role clients | Demonstrates technology feasibility and a credible rollout path. |

## Module D — judge-ready example

For a ₹75,000 high-risk UPI case, Module D does not only say “fraud suspected.” It ranks the 449 cash-out cells, exposes the best candidate zone to the investigator, and sends that destination into the field-dispatch workflow. **Precision@Top-10 of 80%** means the expected zone appears in the top ten ranked response areas in the prototype evaluation.
